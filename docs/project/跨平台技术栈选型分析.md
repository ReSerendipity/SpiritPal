## 1. 分析背景与目标

### 1.1 项目目标

开发一款**桌面端与移动端通用的桌面宠物应用**，需要满足：
- 桌面端：Windows + macOS（Linux 可选）
- 移动端：iOS + Android
- 核心功能：宠物动画、交互、养成系统、AI 聊天、模组生态

### 1.2 分析基础

已完成以下 7 个开源项目的深度技术分析：

| 项目 | 技术栈 | 跨平台支持 | 核心特色 |
|------|--------|------------|----------|
| **Dororo** | Godot 4.4.1 + C# + GDScript + Live2D | Windows only | Live2D 渲染、GDExtension |
| **Ameath** | Python + Tkinter + Pillow | Windows only | 7 个 LLM 服务商、组合式管理器 |
| **Feibi** | Python + Tkinter + Pillow | Windows only | 三段式长期记忆、dataclass 配置 |
| **MurasamePet** | Python + PyQt5 + FastAPI | macOS + Windows | LLM + TTS + VL 完整链路 |
| **EchoBot** | Python + FastAPI + JS + Live2D Web | Web 跨平台 | Decision-Roleplay-Agent 三层架构 |
| **DyberPet** | Python + PySide6 + Fluent-Widgets | Windows + 部分 macOS | 最完整养成系统、JSON 模组 |
| **OC-Claw** | Tauri v2 + React 19 + TS + Rust | macOS + Windows | 跨平台最佳、视频双缓冲动画 |

### 1.3 关键洞察

1. **Python 系项目（5/7）无法支持移动端**：Ameath、Feibi、MurasamePet、DyberPet、EchoBot 均基于 Python，无法迁移到 iOS/Android
2. **OC-Claw 是唯一使用 Tauri v2 的项目**，且已验证 macOS + Windows 双平台
3. **Dororo 使用的 Godot 引擎支持移动端导出**，但桌面端实现较重
4. **EchoBot 的 Web 架构**理论上可通过 PWA 适配移动端
5. **Live2D 渲染**：桌面端用 GDExtension（Dororo），Web 端用 Cubism SDK JS（EchoBot）

## 3. 跨平台技术方案候选评估

### 3.1 候选方案一览

| 方案 | 桌面 | 移动端 | 语言 | 代表项目 | 评价 |
|------|------|--------|------|----------|------|
| **Tauri v2 + React** | ✅ | ✅ | Rust + TS | OC-Claw | ⭐⭐⭐⭐⭐ 推荐 |
| **Flutter** | ✅ | ✅ | Dart | 无 | ⭐⭐⭐⭐ 备选 |
| **React Native + React Native Windows** | ✅ | ✅ | JS/TS | 无 | ⭐⭐⭐ 备选 |
| **Godot Engine** | ✅ | ✅ | GDScript/C# | Dororo | ⭐⭐⭐ 引擎过重 |
| **Web PWA** | ✅ | ✅ | JS/TS | EchoBot | ⭐⭐ 体验受限 |
| **Electron + Capacitor** | ✅ | ✅ | JS/TS | 无 | ⭐⭐ 包体积大 |
| **Qt + Qt Mobile** | ✅ | ⚠️ | C++/Python | DyberPet | ⭐⭐ 移动端支持弱 |

### 3.2 方案详细评估

#### 方案 A：Tauri v2 + React（推荐）

**优势：**
- OC-Claw 已验证桌面端跨平台（macOS + Windows）
- Tauri v2 原生支持 iOS + Android
- Rust 后端性能优秀，包体积小（~20MB）
- React 生态丰富，组件库多
- TypeScript 类型安全
- 可直接复用 OC-Claw 的窗口配置、视频双缓冲等方案
- Web 技术栈（HTML/CSS/JS）跨平台通用

**劣势：**
- Tauri 移动端尚在发展阶段，生态不如 Flutter 成熟
- Rust 学习曲线陡峭
- 移动端透明窗口/悬浮窗实现需探索
- Live2D Web SDK 在移动端 WebView 性能待验证

**技术栈：**
```
前端：React 19 + TypeScript + Tailwind CSS + Motion
后端：Rust + Tauri v2
动画：Live2D Cubism Web SDK / 视频双缓冲 / 精灵图
状态：Zustand / Tauri plugin-store
LLM：OpenAI 兼容 SDK（fetch 调用）
构建：Vite + Tauri CLI
```

#### 方案 B：Flutter

**优势：**
- 一套代码完美支持所有平台（桌面 + 移动）
- Dart 语言简单易学
- 性能优秀（Skia 渲染引擎）
- 原生体验好
- 丰富的 UI 组件库（Material/Cupertino）

**劣势：**
- 7 个项目中无 Flutter 案例，缺乏直接参考
- 桌面端透明窗口/悬浮窗实现需自定义
- Live2D Flutter 支持不成熟
- 桌面端生态不如 Web 技术栈丰富
- 悬浮窗在移动端（iOS）受限

**技术栈：**
```
框架：Flutter 3.x
语言：Dart
状态：Riverpod / Bloc
动画：Flare / 自定义渲染 / 视频
LLM：http 包调用 OpenAI 兼容 API
```

#### 方案 C：React Native + React Native Windows

**优势：**
- 移动端原生体验
- React 生态复用
- TypeScript 类型安全

**劣势：**
- 桌面端支持不成熟（RN Windows 维护缓慢）
- 透明窗口/悬浮窗实现困难
- 无桌面宠物参考案例
- 桌面端性能不如 Tauri

#### 方案 D：Godot Engine

**优势：**
- Dororo 已验证桌面端 Live2D 实现
- 原生支持 iOS/Android 导出
- 游戏引擎性能优秀
- Live2D GDExtension 可复用

**劣势：**
- 引擎过重（197MB）
- 移动端透明窗口/悬浮窗实现复杂
- UI 开发体验不如 Web 技术栈
- 包体积大
- 非 UI 应用标准选择

### 3.3 方案选择结论

**推荐方案：Tauri v2 + React + TypeScript + Rust**

理由：
1. **OC-Claw 已验证**：桌面端跨平台（macOS + Windows）已成功实现
2. **Tauri v2 支持移动端**：原生支持 iOS + Android
3. **包体积小**：~20MB vs Godot 197MB vs Electron 100MB+
4. **技术栈现代**：React 19 + TypeScript + Rust
5. **可直接复用**：OC-Claw 的窗口配置、视频动画、养成系统设计
6. **Web 技术栈通用**：HTML/CSS/JS 跨平台无障碍
7. **Rust 性能**：后端性能优秀，内存安全

## 5. 核心模块技术选型

### 5.1 动画系统

**推荐方案：Live2D Cubism Web SDK + 视频双缓冲 + 精灵图（三选一/可切换）**

| 动画方案 | 适用场景 | 参考项目 | 优劣 |
|----------|----------|----------|------|
| **Live2D Cubism Web SDK** | 高品质二次元角色 | EchoBot | 表现力强，但性能要求高 |
| **视频双缓冲** | 高品质写实动画 | OC-Claw | 效果好，但 .mov alpha 体积大 |
| **精灵图序列帧** | 简单动画/低端设备 | DyberPet/OC-Claw | 兼容性好，但表现力有限 |

**建议**：
- 桌面端默认使用 Live2D（表现力最佳）
- 移动端根据设备性能选择 Live2D 或精灵图
- 视频动画作为高端选项（仅桌面端）

### 5.2 养成系统

**推荐方案：参考 DyberPet 的完整养成系统设计**

```
养成系统
├── 饱食度（HP）— 4 级分级，影响动画概率
├── 好感度（FV）— 256 级 + 徽章体系
├── 金币系统 — 正态分布掉落
├── 物品系统 — 6 分类 + 喜爱度倍率
├── 任务系统 — 番茄钟 + 专注时间
├── 商店系统 — 购买/出售/搜索/筛选
└── Buff 系统 — 临时属性加成
```

**技术实现**：
- 状态管理：Zustand store（`petStore.ts`）
- 持久化：Tauri plugin-store（`pet-data.json`）
- 定时任务：Rust `tokio::time` 或前端 `setInterval`
- 数值配置：JSON 配置文件（参考 DyberPet 的 `settings.py`）

### 5.3 LLM 聊天集成

**推荐方案：OpenAI 兼容 API + SSE 流式 + 三段式长期记忆**

```
LLM 集成架构
├── API 层 — fetch + SSE 流式响应（参考 EchoBot）
├── 记忆系统 — 摘要 + 检索 + 历史（参考 Feibi）
├── Agent 架构 — Decision-Roleplay-Agent 三层（参考 EchoBot）
├── 行为反馈 — 用户行为触发 LLM 反馈（参考 DyberPet）
├── 环境感知 — 感知用户当前应用/时间（参考 DyberPet）
└── 角色定制 — 自定义角色设定（参考 DyberPet）
```

**技术实现**：
- API 调用：前端 `fetch` + `ReadableStream`（SSE 流式）
- 兼容协议：OpenAI Chat Completions API
- 记忆存储：Tauri plugin-store + 向量数据库（可选）
- 上下文管理：自动总结 + token 计数

### 5.4 模组系统

**推荐方案：参考 DyberPet 的 JSON 驱动模组架构**

```
模组系统
├── 角色模组
│   ├── character.json    — 角色配置（参考 DyberPet pet_conf.json）
│   ├── animation.json    — 动画参数（参考 DyberPet act_conf.json）
│   ├── dialogue.json     — 对话配置
│   └── assets/           — 动画资源
├── 物品模组
│   └── items.json        — 物品配置（参考 DyberPet items_config.json）
├── 宠物模组
│   └── pet.json          — 迷你宠物配置
└── 模组管理
    ├── 自动扫描加载
    ├── 错误提示
    └── 模组市场（远期）
```

**技术实现**：
- 模组扫描：Rust 后端扫描模组目录
- 配置解析：serde_json 解析 JSON 配置
- 资源加载：Tauri asset 协议
- 模组管理 UI：React 组件

## 8. 风险与挑战

### 8.1 技术风险

| 风险 | 等级 | 影响 | 缓解方案 |
|------|------|------|----------|
| **Tauri 移动端不成熟** | 高 | 移动端功能受限 | 持续跟踪 Tauri Mobile 发展，准备 Flutter 降级方案 |
| **iOS 无悬浮窗** | 高 | iOS 体验降级 | App 内悬浮 + Widget + Live Activity 降级方案 |
| **Live2D 移动端性能** | 中 | 动画卡顿 | 提供精灵图降级方案，按设备性能选择 |
| **Rust 学习曲线** | 中 | 开发效率 | 核心后端用 Rust，非核心用 TypeScript |
| **移动端后台保活** | 中 | 宠物状态无法实时更新 | 前台服务（Android）+ 推送通知唤醒 |
| **跨平台 UI 一致性** | 低 | 体验不一致 | Tailwind CSS 统一样式，平台特定组件条件渲染 |

### 8.2 产品风险

| 风险 | 等级 | 影响 | 缓解方案 |
|------|------|------|----------|
| **移动端桌面宠物需求不确定** | 中 | 产品方向偏差 | 先做桌面端 MVP，移动端作为增量 |
| **LLM API 成本** | 中 | 运营成本 | 支持用户自带 API Key，本地模型支持 |
| **模组生态冷启动** | 中 | 内容不足 | 内置丰富角色，提供模组创作工具 |
| **App Store 审核** | 中 | iOS 发布延迟 | 遵守平台规范，准备审核被拒预案 |

### 8.3 关键技术挑战

1. **移动端悬浮窗实现**
   - Android：SYSTEM_ALERT_WINDOW 权限 + 前台服务
   - iOS：无原生支持，需降级方案（Widget + App 内悬浮）

2. **Live2D 跨平台渲染**
   - 桌面端：Live2D Cubism Web SDK（WebView）
   - 移动端：同上，但需验证性能
   - 降级：精灵图序列帧

3. **跨平台数据同步**
   - 本地优先：各平台独立存储
   - 云同步（远期）：可选的云端存档同步

4. **LLM 流式响应跨平台**
   - 桌面端：fetch + SSE
   - 移动端：同上（Tauri Mobile WebView 支持）

## 9. 总结与下一步

### 9.1 技术栈选型结论

**推荐技术栈：Tauri v2 + React 19 + TypeScript + Rust**

这一选型基于以下核心判断：

1. **OC-Claw 已验证桌面端可行性**：Tauri v2 + React 的组合在 macOS + Windows 上表现优秀
2. **Tauri v2 原生支持移动端**：一套技术栈覆盖所有平台
3. **包体积最优**：~20MB vs 其他方案 50-200MB
4. **技术栈最现代**：React 19 + TypeScript + Rust + Tailwind v4
5. **可直接复用 OC-Claw 经验**：窗口配置、视频动画、养成系统、国际化

### 9.2 核心设计原则

1. **桌面优先，移动增量**：先做好桌面端 MVP，再扩展移动端
2. **共享业务逻辑，平台适配 UI**：养成系统、LLM 集成、模组系统跨平台共享
3. **渐进式动画方案**：Live2D → 视频 → 精灵图，按设备性能降级
4. **JSON 驱动模组生态**：参考 DyberPet 的模组架构，实现创作自由
5. **LLM 深度集成**：参考 EchoBot + Feibi + DyberPet 的 AI 集成模式

### 9.3 建议的开发路径

```
Phase 1：桌面端 MVP（Windows + macOS）
├── 基础框架搭建（Tauri v2 + React 19）
├── 透明窗口 + 宠物渲染（精灵图）
├── 基础交互（拖拽/点击/喂食）
├── 基础养成系统（HP/FV/金币）

├── 三段式长期记忆

Phase 3：移动端扩展
├── Tauri Mobile 集成
```
