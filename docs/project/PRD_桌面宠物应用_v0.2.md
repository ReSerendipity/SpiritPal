## 1. 产品概述

### 1.1 产品定位

SpiritPal 是一款**跨平台 AI 桌面宠物应用**，以可爱的虚拟宠物角色常驻用户设备，提供情感陪伴、轻量互动和温和生产力辅助。产品核心理念为**「简单却温暖」**——它不是效率工具，而是让用户在忙碌的数字生活中感受到温暖陪伴的存在。

### 1.2 产品愿景

> 让每个人都能在屏幕上拥有一个「越用越懂你」的数字伙伴。

### 1.3 核心价值主张

| 价值维度 | 描述 |
|----------|------|
| **情感陪伴** | 一个有性格、有记忆、会成长的虚拟伙伴 |
| **无打扰共存** | 完全融入工作流，需要时出现，不需要时隐形 |
| **隐私优先** | AI 推理和数据存储均在本地完成，数据不上云 |
| **个性化表达** | 支持自定义角色、性格、互动方式 |
| **跨端一致** | 桌面端和移动端拥有统一的体验和数据 |

### 1.4 产品目标与成功指标

| 目标维度 | 指标 | Phase 1 目标 | Phase 2 目标 |
|----------|------|-------------|-------------|
| **用户留存** | 次日留存率 | >40% | >55% |
| **用户留存** | 7 日留存率 | >20% | >30% |
| **用户粘性** | 日均使用时长 | >15 分钟 | >30 分钟 |
| **互动频次** | 日均交互次数 | >10 次 | >25 次 |
| **AI 使用** | 日均对话轮次 | >5 轮 | >15 轮 |
| **性能** | 冷启动时间 | <2s | <2s |
| **性能** | 内存占用 | <80MB | <80MB |
| **安装包** | 桌面端大小 | <30MB | <30MB |

### 1.5 产品名称候选

- **SpiritPal** — 宠物伙伴
- **MochiPet** — 麻薯宠物（可爱感）
- **DeskMate** — 桌面伙伴

> 当前暂定 **SpiritPal**，最终名称待确认。

## 2. 问题陈述

### 2.1 现状与痛点

当前桌面宠物/虚拟伴侣市场存在以下核心问题：

| 痛点 | 现状描述 | 影响 |
|------|----------|------|
| **平台割裂** | 绝大多数桌面宠物仅支持 Windows（DyberPet/VPet/你的AI桌宠），无跨平台方案 | 50%+ 非 Windows 用户无法使用 |
| **AI 隐私风险** | AI 桌宠普遍依赖云端 API（OpenAI 等），对话数据上传第三方服务器 | 用户隐私泄露风险，离线不可用 |
| **缺乏长期记忆** | 多数产品无记忆或仅简单上下文，无法"越用越懂你" | 用户无法建立情感连接 |
| **打扰式提醒** | 传统桌面应用使用弹窗/通知提醒，干扰用户工作流 | 用户反感并关闭提醒功能 |
| **角色个性化不足** | 多数产品仅支持预设角色，缺乏深度性格定制 | 用户缺乏个性化表达途径 |
| **移动端无解** | 桌面宠物无法延伸到手机端，数据无法跨端同步 | 用户出门后失去陪伴 |

### 2.2 数据支撑

- 桌面宠物类应用在 Steam/应用商店持续增长，BongoCat（Tauri 实现）获得 9.6k+ stars
- DyberPet（Python 桌面宠物）拥有活跃的社区和模组生态
- AI 聊天类应用（Character.ai 等）日活超千万，验证了用户对 AI 陪伴的需求
- 隐私顾虑是 AI 应用用户流失的首要原因

### 2.3 我们的解决方案

SpiritPal 通过以下方式解决上述痛点：

| 痛点 | 解决方案 |
|------|----------|
| 平台割裂 | Tauri v2 一套代码覆盖桌面 + 移动端 |
| AI 隐私 | 本地 LLM（Ollama）优先，云端可选 |
| 缺乏记忆 | 四段式增强记忆（实时/对话/语义/情景） |
| 打扰式提醒 | 宠物行为提醒（动画+气泡）替代弹窗 |
| 角色个性化 | 五维性格模型 + AI 辅助创建 + 模组生态 |
| 移动端无解 | 全屏 Live2D + Widget + 推送通知 |

## 3. 范围定义

| 自动行为（随机漫步/睡觉/发呆） | 宠物生命力 |

**Phase 3+（Could Have）：**

| 范围 | 内容 |

| 企业版/B端功能 | 聚焦 C 端个人用户 |

## 4. 目标用户与场景

### 4.1 目标用户群

| 用户类型 | 核心需求 | 使用场景 |
|----------|----------|----------|
| **上班族/程序员** | 轻量陪伴、不打扰工作、柔性提醒 | 工作时桌面常驻，摸鱼互动 |
| **独居青年** | AI 聊天、长期记忆、情绪感知 | 下班后与宠物对话，寻求陪伴 |
| **二次元爱好者** | 精美 Live2D 角色、自定义导入 | 收集/创作角色，社区分享 |
| **学生党** | 低占用、趣味互动、养成系统 | 学习时专注陪伴，碎片时间互动 |
| **不养宠物人群** | 低负担的数字替代 | 随时互动，无需真实养宠责任 |

### 4.2 核心用户画像

**画像 A：小王（程序员，28岁）**
- 工作时喜欢有东西在屏幕上陪着，但讨厌被打扰
- 期望桌宠能感知他的工作状态（编码/摸鱼/开会），做出不同反应
- 想要一个番茄钟，但不想要弹窗提醒，而是宠物用动作提醒他

**画像 B：小李（独居，25岁）**
- 下班回家后感到孤单，想要一个能聊天的伙伴
- 期望宠物能记住她的喜好和对话历史，越聊越懂她
- 希望在手机上也能看到宠物，出门在外也能互动

**画像 C：小张（二次元爱好者，20岁）**
- 想把自己喜欢的动漫角色设为桌宠
- 期望社区能分享和下载角色模组
- 在 B 站/小红书看到别人分享桌宠截图，想自己也弄一个

### 4.3 用户场景分析

#### 场景 1：工作日早晨启动

```
小王开机 → SpiritPal 自动启动并最小化到托盘 → 小王开始编码
→ 宠物检测到 IDE 窗口为前台，播放"安静陪伴"动画
→ 小王工作 25 分钟后，宠物伸懒腰 + 气泡提示"休息一下吧~"
→ 小王摸摸宠物头，获得 +2 好感度
```

#### 场景 2：下班后聊天陪伴

```
小李打开聊天窗口 → "今天好累啊"
→ 宠物回忆相关记忆："记得你上周也说很累，那天你完成了那个大项目呢"
→ 小李感到被理解，继续倾诉工作中的烦恼
→ 宠物根据五维性格（温暖=0.8）用温暖的方式回应
→ 对话结束后，LLM 提取记忆："用户工作压力较大，项目截止日临近"
```

#### 场景 3：角色切换与自定义

```
小张想换个角色 → 右键菜单 → 换装 → 选择"墨墨"（毒舌黑猫）
→ 宠物淡出 → 新角色淡入 → "哼，换我了是吧"
→ 小张调整性格参数：温度调低，直率调高
→ 小张创建自定义角色："帮我创建一个话很多的元气少女"
→ AI 自动生成角色设定和五维参数
```

#### 场景 4：长时间记忆触发

```
距离小李生日还有 3 天
→ 宠物自动检测到时间锚点
→ 气泡提示："还有3天就是你的生日了！去年你说想要一只猫..."
→ 小李感动，与宠物的对话中好感度提升
→ 宠物获得"贴心"成就
```

#### 场景 5：移动端联动

```
小王出门在外 → 手机 Widget 显示宠物状态（HP=60, FV=320）
→ 点击 Widget 快捷喂食 → 宠物收到食物并回复"谢谢主人！"
→ 小王收到推送通知："主人不在的时候我好想你~"
```

### 5.2 差异化定位

| 差异点 | SpiritPal 的做法 | 竞品的做法 |
|--------|--------------|------------|
| **跨平台** | Tauri v2 一套代码覆盖桌面+移动端 | 多数仅 Windows |
| **隐私 AI** | 本地 LLM（Ollama）+ 云端可选 | 多数依赖云端 API |
| **不打扰** | 情境感知 + 宠物动作提醒（非弹窗） | 弹窗/通知轰炸 |
| **长记忆** | 四段式记忆（实时+对话+语义+情景） | 简单上下文或无记忆 |
| **角色个性化** | 五维性格参数 + AI 生成 + 一致性保障 | 固定预设或简单 Prompt |
| **模组生态** | JSON 驱动 + 社区创作工具 | 多数不支持或门槛高 |
| **轻量级** | 安装包 <30MB，运行内存 <80MB | 多数 100MB+ |

### 3.3 市场空白

1. **AI + 桌面宠物的深度融合**：多数产品 AI 功能浅薄，缺乏长期记忆和情境感知
2. **跨平台一致性**：桌面端和移动端割裂，无统一体验
3. **隐私保护**：AI 产品多数依赖云端，缺乏本地运行选项
4. **角色个性化**：缺乏深度性格定制和 AI 辅助创建能力
5. **记忆感知**：用户无法感知宠物的"记忆力"，缺乏情感连接
6. **模组生态**：用户创作和分享的门槛高

```html
<!-- OC-Claw 验证的双缓冲方案：两个 video 元素交替播放，消除切换闪烁 -->
<div id="pet-animation">

  <video id="video-b" autoplay muted playsinline style="display:none"></video>
</div>
```

| 性格维度 | 高值表现 | 低值表现 |
|----------|----------|----------|
| 温度 | 问候频繁、语气词多（呀/呢/哦）、关心鼓励 | 简洁克制、偶尔吐槽 |

| 依赖 | 主动索要互动、离线抱怨、分离焦虑 | 独立、偶尔互动 |

#### 7.3.3 System Prompt 合成与角色一致性

**合成架构：**
```
角色五维参数 + 用户画像(记忆) + Few-shot 示例
    → Prompt 合成引擎 → 完整 System Prompt
    → LLM 推理
    → 后处理引擎（语气校验 + 动作标签提取 + 情感分析 + 记忆触发判断）
```

> **架构借鉴**：EchoBot 的 Decision-Roleplay-Agent 三层分离模式 — 将"决策层"（工具调用/任务管理）与"角色扮演层"（人设一致性）分离，避免工具调用破坏角色性格。SpiritPal 可借鉴此模式，在 System Prompt 中明确区分"角色回复"和"系统指令"两部分。

**一致性保障机制：**

| 机制 | 描述 |
|------|------|
| 性格锚定 | 每次对话注入五维参数的自然语言描述，防止 LLM 人设漂移 |
| Few-shot 示例 | 角色设定中包含 3-5 组示例对话 |
| 后处理校验 | 关键词匹配 + LLM 自评（低频调用） |
| 用户反馈环 | 用户可标记"不符合性格"的回复 |

### 7.4 F3 记忆与交互系统

#### 7.4.1 四段式记忆架构

```
┌─────────────────────────────────────────────────────────┐
│                  四段式增强记忆系统                         │
├─────────────────────────────────────────────────────────┤
│  第一段：实时上下文（Working Memory）                      │
│  - 当前对话的最近 N 轮消息，动态压缩                        │
│  - Token 范围：2,500 ~ 100,000（用户可调）                │
│                                                          │
│  第二段：对话记忆（Episodic Memory）                       │
│  - 历史对话的结构化摘要 + 语义向量索引                      │
│  - 自动提取关键事件（生日/喜好/重要决定）                    │
│                                                          │
│  第三段：语义记忆（Semantic Memory）                       │
│  - 用户画像（偏好/习惯/性格推断）                           │
│  - 关系图谱（用户提到的人/事/物的关联）                      │
│                                                          │
│  第四段：情景记忆（Autobiographical Memory）               │
│  - 里程碑事件（第一次对话/等级提升）                         │
│  - 时间锚点（"去年这个时候你..."）                          │
│  - 情感快照（高情感强度时刻的完整记录）                      │
└─────────────────────────────────────────────────────────┘
```

#### 7.4.2 记忆触发机制

| 触发类型 | 触发条件 | 回忆方式 | 示例 |
|----------|----------|----------|------|
| **对话触发** | 用户提到相关关键词 | 自然融入回复 | "记得你上次加班到很晚..." |
| **时间触发** | 到达时间锚点 | 主动发起 | 生日/纪念日提醒 |
| **情境触发** | 当前情境与历史相似 | 气泡提示 | 深夜使用时回忆 |
| **周期触发** | 纪念日/节日 | 主动回忆 | "认识第100天！" |
| **成就触发** | 达成里程碑 | 庆祝+回忆 | FV 升级统计回顾 |
| **情感触发** | 用户情绪变化 | 共情+回忆 | 难过时回忆安慰经历 |

#### 7.4.3 离线降级记忆方案（借鉴 Feibi）

当本地无向量检索模型或设备性能不足时，采用 Feibi 的零依赖轻量方案：

| 组件 | 在线方案 | 离线降级方案（Feibi） |

#### 7.4.3 记忆优先级与生命周期

**重要性评分：** 基础分（用户要求记住的事 100 分 / 个人信息 90 分 / 情感时刻 80 分 / 偏好 70 分 / 普通摘要 40 分 / 闲聊 20 分）× 时间因子 × 访问因子 × 情感因子

**生命周期：** 热记忆（7天/500条）→ 温记忆（7-90天/2000条）→ 冷记忆（90天+/1000条）→ 归档（365天+/500条）

## 15. 数据埋点与分析

### 15.1 核心指标定义

| 指标名称 | 计算方式 | 采集时机 | 业务目标 |
|----------|----------|----------|----------|
| 日活跃用户（DAU） | 当日启动应用的独立用户数 | 应用启动 | 衡量用户规模 |
| 次日留存率 | 次日启动用户 / 当日启动用户 | 每日计算 | 衡量产品粘性 |
| 日均交互次数 | 用户点击/拖拽/喂食总次数 / DAU | 每日聚合 | 衡量互动深度 |
| 日均对话轮次 | AI 对话总轮次 / DAU | 每日聚合 | 衡量 AI 使用率 |
| 功能使用率 | 各功能使用人数 / DAU | 每日聚合 | 衡量功能价值 |
| 崩溃率 | 崩溃次数 / 启动次数 | 持续采集 | 衡量稳定性 |

### 15.2 埋点事件列表

| 事件名 | 触发时机 | 上报字段 |
|--------|----------|----------|
| `app_launch` | 应用启动 | platform, version, is_autostart |
| `pet_interaction` | 用户与宠物交互 | type(click/drag/feed/pet), duration |
| `chat_send` | 用户发送消息 | message_length, model |
| `chat_receive` | AI 回复完成 | response_length, model, latency_ms |
| `memory_trigger` | 记忆触发回忆 | trigger_type, memory_id |
| `item_use` | 使用物品 | item_id, item_type |
| `tomato_complete` | 完成番茄钟 | duration_minutes |
| `setting_change` | 修改设置 | setting_key, old_value, new_value |
| `mod_install` | 安装模组 | mod_id, mod_name |
| `image_switch` | 切换形象 | from_image, to_image |

### 15.3 数据安全

| 原则 | 实施方式 |
|------|----------|
| **本地优先** | 所有数据默认本地存储，不上传服务器 |
| **匿名化** | 埋点数据不包含用户个人信息 |
| **可关闭** | 用户可在设置中完全关闭数据采集 |
| **可删除** | 用户可随时删除所有本地数据 |
