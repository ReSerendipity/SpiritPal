## 1. 产品概述

### 1.1 产品定位

SpiritPal 是一款**跨平台 AI 桌面宠物应用**，以可爱的虚拟宠物角色常驻用户设备，提供情感陪伴、轻量互动和温和生产力辅助。产品核心理念为**「简单却温暖」**——它不是效率工具，而是让用户在忙碌的数字生活中感受到温暖陪伴的存在。

### 1.2 产品愿景

> 让每个人都能在屏幕上拥有一个「越用越懂你」的数字伙伴。

### 1.3 核心价值主张

| 价值维度 | 描述 |
|----------|------|
| **情感陪伴** | 一个有性格、有记忆、会成长的虚拟伙伴 |
| **无打扰共存** | 完全融入工作流，需要时出现，不需要时隐形 |
| **隐私优先** | AI 推理和数据存储均在本地完成，数据不上云 |
| **个性化表达** | 支持自定义角色、性格、互动方式 |
| **跨端一致** | 桌面端和移动端拥有统一的体验和数据 |

### 1.4 产品名称候选

- **SpiritPal** — 宠物伙伴
- **MochiPet** — 麻薯宠物（可爱感）
- **DeskMate** — 桌面伙伴

> 当前暂定 **SpiritPal**，最终名称待确认。

## 2. 目标用户与画像

### 2.1 目标用户群

| 用户类型 | 核心需求 | 使用场景 |
|----------|----------|----------|
| **上班族/程序员** | 轻量陪伴、不打扰工作、柔性提醒 | 工作时桌面常驻，摸鱼互动 |
| **独居青年** | AI 聊天、长期记忆、情绪感知 | 下班后与宠物对话，寻求陪伴 |
| **二次元爱好者** | 精美 Live2D 角色、自定义导入 | 收集/创作角色，社区分享 |
| **学生党** | 低占用、趣味互动、养成系统 | 学习时专注陪伴，碎片时间互动 |
| **不养宠物人群** | 低负担的数字替代 | 随时互动，无需真实养宠责任 |

### 2.2 核心用户画像

**画像 A：小王（程序员，28岁）**
- 工作时喜欢有东西在屏幕上陪着，但讨厌被打扰
- 期望桌宠能感知他的工作状态（编码/摸鱼/开会），做出不同反应
- 想要一个番茄钟，但不想要弹窗提醒，而是宠物用动作提醒他

**画像 B：小李（独居，25岁）**
- 下班回家后感到孤单，想要一个能聊天的伙伴
- 期望宠物能记住她的喜好和对话历史，越聊越懂她
- 希望在手机上也能看到宠物，出门在外也能互动

**画像 C：小张（二次元爱好者，20岁）**
- 想把自己喜欢的动漫角色设为桌宠
- 期望社区能分享和下载角色模组
- 在 B 站/小红书看到别人分享桌宠截图，想自己也弄一个

## 3. 竞品分析与差异化

### 3.1 竞品矩阵

| 竞品 | 平台 | AI 能力 | 养成系统 | 自定义角色 | 跨平台 | 定价 |
|------|------|---------|----------|------------|--------|------|
| **BongoCat** | Win/Mac/Linux | ❌ | ❌ | ✅ Live2D | ❌ 仅桌面 | 免费 |
| **WindowPet** | Win/Mac/Linux | ❌ | ❌ | ✅ 图片 | ❌ 仅桌面 | 免费 |
| **DyberPet** | Win(部分Mac) | ✅ LLM | ✅ 完整 | ✅ JSON模组 | ❌ 仅桌面 | 免费+闭源AI |
| **你的AI桌宠** | Steam | ✅ GPT | ✅ 基础 | ✅ Live2D | ❌ 仅Win | ¥19 |
| **Deskie** | Steam | ✅ 火山引擎 | ✅ 基础 | ✅ Live2D | ❌ 仅Win | 免费 |
| **VPet** | Win | ❌ | ✅ 完整 | ✅ 创意工坊 | ❌ 仅Win | 免费 |
| **SpiritPal（本产品）** | **全平台** | **✅ 本地AI** | **✅ 完整** | **✅ Live2D+模组** | **✅** | **免费+增值** |

### 3.2 差异化定位

| 差异点 | SpiritPal 的做法 | 竞品的做法 |
|--------|--------------|------------|
| **跨平台** | Tauri v2 一套代码覆盖桌面+移动端 | 多数仅 Windows |
| **隐私 AI** | 本地 LLM（Ollama）+ 云端可选 | 多数依赖云端 API |
| **不打扰** | 情境感知 + 宠物动作提醒（非弹窗） | 弹窗/通知轰炸 |
| **长记忆** | 三段式记忆（摘要+检索+历史） | 简单上下文或无记忆 |
| **模组生态** | JSON 驱动 + 社区创作工具 | 多数不支持或门槛高 |
| **轻量级** | 安装包 <30MB，运行内存 <80MB | 多数 100MB+ |

### 3.3 市场空白

1. **AI + 桌面宠物的深度融合**：多数产品 AI 功能浅薄，缺乏长期记忆和情境感知
2. **跨平台一致性**：桌面端和移动端割裂，无统一体验
3. **隐私保护**：AI 产品多数依赖云端，缺乏本地运行选项
4. **生产力辅助**：桌宠被视为干扰而非助手，缺乏柔性提醒机制
5. **模组生态**：用户创作和分享的门槛高

### 4.2 窗口架构

桌面端采用**双窗口架构**（参考 BongoCat）：

| 窗口 | 用途 | 特性 |
|------|------|------|
| **主窗口（PetWindow）** | 宠物渲染 + 交互 | 透明、无边框、置顶、点击穿透、可拖拽 |
| **设置窗口（SettingsWindow）** | 设置/商店/聊天/仪表盘 | 标准窗口，通过托盘图标或右键菜单打开 |

移动端采用**单窗口全屏架构**：

| 窗口 | 用途 | 特性 |
|------|------|------|
| **主窗口（PetScreen）** | 宠物 + 聊天 + 养成 | 全屏应用，底部 Tab 导航 |

### 5.2 F1 宠物系统

#### F1.1 宠物渲染

**桌面端渲染方案（优先级：Live2D > 精灵图 > 视频）：**

| 方案 | 技术 | 适用场景 | 参考项目 |
|------|------|----------|----------|
| **Live2D** | pixi-live2d-display + Pixi.js | 高品质二次元角色（默认） | BongoCat |
| **精灵图序列帧** | Canvas 2D / CSS 动画 | 低端设备降级 / 像素风格 | DyberPet |
| **视频双缓冲** | HTML5 `<video>` + alpha | 高品质写实动画 | OC-Claw |

**移动端渲染方案：**

| 方案 | 说明 |
|------|------|
| **Live2D（默认）** | iOS WKWebView / Android WebView 均支持 WebGL |
| **精灵图降级** | 低端设备自动降级 |

**F1.1.1 Live2D 渲染需求：**

| 需求 ID | 需求描述 | 优先级 | 平台 |
|---------|----------|--------|------|
| F1.1.1-1 | 支持 Live2D Cubism 4/5 模型（.model3.json） | P0 | 全平台 |
| F1.1.1-2 | 模型文件通过 Tauri `convertFileSrc()` 加载 | P0 | 桌面 |
| F1.1.1-3 | 支持模型表情（exp3.json）切换 | P0 | 全平台 |
| F1.1.1-4 | 支持模型动作（motion3.json）播放 | P0 | 全平台 |
| F1.1.1-5 | 支持物理模拟（头发/衣服摆动） | P1 | 全平台 |
| F1.1.1-6 | 透明背景渲染（与透明窗口配合） | P0 | 桌面 |
| F1.1.1-7 | 性能自适应：根据设备性能调整渲染质量 | P1 | 全平台 |

#### F1.2 宠物动画

**动画分类：**

| 类别 | 动作列表 | 数量 | 触发方式 |
|------|----------|------|----------|
| **基础动作** | idle、sleep、walk、sit | 10+ | 自动/随机 |
| **交互动作** | headpat、feed、drag、poke、wave | 15+ | 用户触发 |
| **情绪动作** | happy、sad、angry、shy、excited | 20+ | 状态驱动 |
| **情境动作** | work、study、focus、rest、music | 15+ | 环境感知 |
| **特殊动作** | birthday、holiday、seasonal | 10+ | 时间触发 |
| **AI 聊天动作** | thinking、surprised、laugh、nod | 10+ | LLM 驱动 |

**F1.2.1 动画需求：**

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F1.2.1-1 | 内置至少 50 种动画动作 | P0 |
| F1.2.1-2 | 支持动画状态机（idle → walk → sit 等自然过渡） | P0 |
| F1.2.1-3 | 饱食度影响动画概率（参考 DyberPet 概率矩阵） | P1 |

| F1.2.1-5 | 模组可扩展动画（JSON 配置 + PNG/模型资源） | P0 |

#### F1.3 自动行为

宠物在无用户交互时的自主行为：

| 行为 | 描述 | 频率 |
|------|------|------|
| 随机漫步 | 在屏幕边缘/任务栏区域来回走动 | 高 |
| 发呆 | 站在原地左右看 | 中 |
| 睡觉 | 夜间或长时间无交互时睡觉 | 低 |
| 伸懒腰 | 长时间 idle 后触发 | 低 |
| 观察屏幕 | 头部跟随鼠标/注视屏幕内容 | 持续 |

#### F1.4 情境感知

| 感知维度 | 实现方式 | 应用 |
|----------|----------|------|
| **时间** | 系统时钟 | 白天活跃/夜晚睡觉 |
| **工作状态** | 桌面端：活动窗口检测；移动端：前台/后台 | 编码时安静/摸鱼时互动 |
| **天气** | 可选：API 获取本地天气 | 下雨天宠物打伞 |
| **音乐** | 可选：系统媒体信息 | 听歌时宠物跟着摇摆 |
| **屏幕内容** | 可选：OCR/截图分析 | 识别宠物出现在截图中 |

### 5.4 F3 养成系统

> 养成系统核心设计参考 DyberPet（7 个项目中最完整的养成系统）

#### F3.1 饱食度（HP）

| 参数 | 值 | 说明 |
|------|-----|------|
| 范围 | 0 - 100 | |
| 等级 | 4 级：饿昏(0) / 饥饿(1-49) / 正常(50-79) / 活力(80-100) | |
| 衰减 | 每小时 -2，睡眠时 -1 | |

**F3.1.1 HP 需求：**

```
│  └─────────────────────────────────────┘   │

│  ┌─────────────────────────────────────┐   │

│                                             │
└─────────────────────────────────────────────┘
```

### 6.3 数据流架构

```
用户交互（点击/拖拽/喂食）
        ↓
React 组件（Event Handler）
        ↓
Zustand Store（状态更新）
        ↓  ← 定时器（HP/FV 衰减）
        ↓  ← LLM 响应（AI 聊天）
        ↓
Tauri IPC（invoke / emit / listen）
        ↓
Rust 后端（命令处理）
        ├── 窗口管理（透明/置顶/穿透）
        ├── 数据存储（SQLite / plugin-store）
        ├── 模组管理（扫描/加载）
        ├── 系统交互（托盘/通知/自启）
        └── AI 桥接（Ollama 检测）
```

|------|------|--------|
| API Key 加密存储 | 不明文存储，使用系统 Keychain/Keystore | P0 |

### 8.4 可维护性要求

| 需求 | 说明 | 优先级 |

## 10. UI/UX 设计规范

### 10.1 设计原则

| 原则 | 描述 |
|------|------|
| **无打扰** | 宠物默认安静存在，不主动打扰用户 |
| **一致性** | 桌面端和移动端保持统一的视觉语言和交互模式 |
| **渐进式** | 首次使用简单，高级功能可探索发现 |
| **情感化** | 每个交互都有情感反馈，让宠物「活」起来 |
| **轻量化** | UI 元素轻盈，不抢占视觉焦点 |

### 10.2 视觉风格

| 维度 | 规范 |
|------|------|
| **主色调** | 柔和暖色系（参考 DyberPet 的 Fluent-Widgets 风格） |
| **字体** | 系统字体栈（`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`） |
| **圆角** | 统一 12px 圆角 |
| **阴影** | 轻微投影，营造悬浮感 |
| **动画** | 平滑过渡 200-300ms，弹性动画使用 `spring` |
| **暗色模式** | 跟随系统或手动切换 |

### 10.3 交互规范

| 交互 | 桌面端 | 移动端 |
|------|--------|--------|
| **选中/激活** | 鼠标 hover 高亮 | 手指按压反馈 |
| **拖拽** | 鼠标左键拖拽 | 手指拖拽 |
| **菜单** | 右键菜单 | 长按菜单 |
| **滚动** | 鼠标滚轮 | 手指滑动 |
| **缩放** | Ctrl+滚轮 | 双指捏合 |
| **返回** | Esc / 关闭按钮 | 手势返回 / 底部 Tab |

### 10.4 宠物窗口设计

**桌面端宠物窗口：**
- 透明背景，仅渲染宠物本身
- 默认大小：200×200px（可缩放 0.5x - 3.0x）
- 默认位置：屏幕右下角（任务栏上方）
- 可拖拽到任意位置
- 边缘检测：拖拽到屏幕边缘时自动吸附

**移动端宠物界面：**
- 全屏应用，Live2D 宠物居中
- 底部半透明 Tab 导航栏
- 顶部状态栏（HP/FV/金币）
- 手势交互：点击/滑动/捏合

#### 15.4.2 角色一致性保障机制

| 机制 | 描述 | 实现方式 |
|------|------|----------|
| **性格锚定** | 每次对话注入性格参数，防止 LLM 人设漂移 | System Prompt 中嵌入五维参数的自然语言描述 |
| **对话示例** | 提供 Few-shot 示例，规范输出格式 | 角色设定中包含 3-5 组示例对话 |
| **后处理校验** | 检查回复是否符合角色设定 | 关键词匹配 + LLM 自评（低频调用） |
| **用户反馈环** | 用户可标记"不符合性格"的回复 | 收集反馈用于微调 System Prompt |
| **版本锁定** | 角色设定变更需用户确认 | 角色配置文件带版本号，变更时提示 |

```typescript
interface CharacterProfile {
```

#### 16.1.1 开机自启动

> 参考 OC-Claw 的 `autostart_on_launch` 配置模式

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| **开机自启动** | **开启（true）** | 安装后默认启用，用户可在设置中关闭 |
| **启动参数** | `--minimized` | 自启动时携带最小化参数 |
| **自启检测** | 启动时检测 | 若检测到非首次启动且无 `--minimized` 参数，正常显示 |

**实现方案：**

| 平台 | 技术方案 | 说明 |
|------|----------|------|
| **Windows** | `tauri-plugin-autostart` + 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 标准 Windows 自启方式 |
| **macOS** | `tauri-plugin-autostart` + LaunchAgent (`~/Library/LaunchAgents/`) | macOS 标准自启方式 |
| **Linux** | `.desktop` 文件放入 `~/.config/autostart/` | XDG autostart 规范 |

**Rust 端实现参考（基于 OC-Claw autostart.rs）：**

```rust
// src-tauri/src/platform/autostart.rs
use tauri::AppHandle;
use tauri_plugin_autostart::ManagerExt;

/// 初始化自启动配置
pub fn setup_autostart(app: &AppHandle) -> Result<(), Box<dyn std::error::Error>> {
    let autostart = app.autolaunch();
    
    // 默认启用自启动（首次安装时）
    let settings = app.state::<crate::storage::AppSettings>();
    if settings.autostart_enabled {
        if !autostart.is_enabled()? {
            autostart.enable()?;
        }
    } else {
        if autostart.is_enabled()? {
            autostart.disable()?;
        }
    }
    
    Ok(())
}

/// 切换自启动状态
pub fn toggle_autostart(app: &AppHandle, enabled: bool) -> Result<(), Box<dyn std::error::Error>> {
    let autostart = app.autolaunch();
    
    if enabled {
        autostart.enable()?;
    } else {
        autostart.disable()?;
    }
    
    Ok(())
}
```

**前端实现：**

```typescript
// src/stores/settingsStore.ts 中的启动逻辑
import { invoke } from '@tauri-apps/api/core';
import { getCurrentWindow } from '@tauri-apps/api/window';

export async function handleLaunchBehavior(): Promise<void> {
  const settings = useSettingsStore.getState();
  const isFirstLaunch = !localStorage.getItem('hasLaunchedBefore');
  const window = getCurrentWindow();
  
  if (isFirstLaunch) {
    // 首次启动：显示引导界面
    localStorage.setItem('hasLaunchedBefore', 'true');
    await window.show();
    await window.setFocus();
    return;
  }
  
  // 非首次启动：检查是否需要最小化
  if (settings.minimizeOnLaunch) {
    await window.hide();
    
    // 显示一条托盘通知提示已启动
    await invoke('show_tray_notification', {
      title: 'SpiritPal',
      body: '已启动并最小化到托盘，点击图标查看宠物'
    });
  } else {
    await window.show();
  }
}
```

```
│  │  - 周期回忆（纪念日/节日自动触发）                   │   │
│  │  - 存储：SQLite + 时间索引                          │   │
│  └──────────────────────────────────────────────────┘   │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### 18.1.2 记忆深度与持久性增强

| 维度 | 原方案 | 增强方案 | 改进说明 |
|------|--------|----------|----------|
| **存储深度** | 摘要 + 向量 | 摘要 + 向量 + 结构化事件 + 时间锚点 | 多维度记忆存储 |
| **检索精度** | 语义检索 | 语义检索 + 时间检索 + 情感检索 + 关联检索 | 多路径检索 |
| **衰减机制** | 简单时间衰减 | 时间衰减 × 重要性加权 × 访问频率 | 更智能的遗忘曲线 |
| **触发回忆** | 被动检索 | 主动触发 + 被动检索 + 周期触发 + 情境触发 | 多种触发机制 |
| **记忆容量** | 无上限 | 分级存储（热/温/冷），冷记忆压缩归档 | 可控的存储增长 |
| **跨形象** | 未定义 | 记忆跨形象持续，换装不丢失记忆 | 统一记忆空间 |

### 18.2 记忆触发机制

#### 18.2.1 触发类型

| 触发类型 | 触发条件 | 回忆方式 | 示例 |
|----------|----------|----------|------|
| **对话触发** | 用户提到与记忆相关的关键词 | 自然融入回复 | 用户："今天好累" → "记得你上次加班到很晚，那次你说终于完成了项目，特别开心" |
| **时间触发** | 到达某个时间锚点 | 主动发起对话 | 用户生日："去年的今天你告诉我你生日，转眼又一年啦！生日快乐！" |
| **情境触发** | 当前情境与历史情境相似 | 气泡提示 | 深夜使用："又是一个深夜呢，上次你这么晚还在，是因为那个紧急 bug 对吧？" |
| **周期触发** | 纪念日/节日/定期回顾 | 主动回忆 | "今天是我们认识第 100 天呢！还记得第一天你说想养一只猫..." |
| **成就触发** | 达成某个里程碑 | 庆祝 + 回忆 | FV 升级："从 1 级到 64 级，你摸了我 847 次头，喂了 236 次食物！" |
| **情感触发** | 检测到用户情绪变化 | 共情 + 回忆 | 用户表达难过："你上次难过是 3 月 15 号，那天你说工作压力很大...这次是什么事呢？" |

#### 18.2.2 触发频率控制

为避免"记忆过度"造成困扰，需控制触发频率：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **最大主动回忆/天** | 5 次 | 宠物主动触发回忆的每日上限 |
| **最小间隔** | 30 分钟 | 两次主动回忆的最小间隔 |
| **被动回忆率** | 30% | 对话中被动检索到相关记忆时注入的概率 |
| **新记忆冷却** | 1 小时 | 刚存储的记忆不会立即被触发 |
| **用户反感检测** | 开启 | 连续 3 次用户忽略回忆则降低频率 |

### 18.3 记忆优先级管理系统

#### 18.3.1 记忆重要性评分模型

```
记忆重要性分数 = 基础分 × 时间因子 × 访问因子 × 情感因子

基础分（人工规则）：
  ├── 用户主动要求记住的事 → 100 分
  ├── 重要个人信息（生日/名字/职业） → 90 分
  ├── 情感强烈时刻 → 80 分
  ├── 用户偏好/习惯 → 70 分
  ├── 普通对话摘要 → 40 分
  └── 日常闲聊 → 20 分

时间因子：
  最近 7 天：×1.0
  最近 30 天：×0.8
  最近 90 天：×0.6
  超过 90 天：×0.4

访问因子：
  被检索 >5 次：×1.5
  被检索 2-5 次：×1.0
  被检索 1 次：×0.8
  从未被检索：×0.5

情感因子：
  高情感强度：×1.3
  中情感强度：×1.0
  低情感强度：×0.7
```

#### 18.3.2 记忆生命周期管理

```
新记忆产生
    ↓
┌──────────────┐
│  热记忆池     │ ← 最近 7 天的所有记忆（完整保留）
│  (Hot)        │
└──────┬───────┘
       ↓ 超过 7 天
┌──────────────┐
│  温记忆池     │ ← 7-90 天，压缩摘要，按重要性排序
│  (Warm)       │
└──────┬───────┘
       ↓ 超过 90 天
┌──────────────┐
│  冷记忆池     │ ← 90 天以上，仅保留高重要性记忆的摘要
│  (Cold)       │
└──────┬───────┘
       ↓ 超过 365 天
┌──────────────┐
│  归档池       │ ← 仅保留里程碑事件和高重要性记忆
│  (Archive)    │
└──────────────┘
```

```typescript
  });
  
  // 3. 同时发送系统通知（可配置）
  if (settingsStore.getState().notificationsEnabled) {
    await invoke('send_notification', {
      title: 'SpiritPal 提醒',
      body: event.title,
    });
  }
}
```

#### 19.4.3 工作状态感知模块

> 参考 OC-Claw 的 `active_window_monitor` 和 DyberPet 的 `app_counter`

| 平台 | 检测方式 | 说明 |
|------|----------|------|
| **Windows** | `GetForegroundWindow()` + `GetWindowText()` | 获取当前活动窗口标题 |
| **macOS** | `NSWorkspace.shared.frontmostApplication` | 获取前台应用信息 |
| **Linux** | `xdotool getactivewindow` | 获取活动窗口 |

**工作状态分类：**

| 状态 | 检测条件 | 宠物行为 |
|------|----------|----------|
| **编码** | 活动窗口为 IDE（VS Code/IntelliJ 等） | 宠物安静陪伴，偶尔看屏幕 |
| **浏览** | 活动窗口为浏览器 | 宠物安静陪伴 |
| **文档** | 活动窗口为 Word/PPT/Notion | 宠物安静陪伴 |
| **摸鱼** | 活动窗口为社交/娱乐/游戏 | 宠物开心/一起看 |
| **空闲** | 无活动窗口（5分钟+） | 宠物发呆/睡觉 |
| **开会** | 活动窗口为会议软件（Zoom/腾讯会议） | 宠物安静不打扰 |
