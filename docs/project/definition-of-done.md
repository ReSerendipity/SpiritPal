# Definition of Done (DoD) — 完成定义

> **文档编号**：DOD-001  
> **创建日期**：2026-08-27  
> **适用范围**：SpiritPal 全项目所有功能开发任务

---

## 1. 目的

明确「什么算完成」的标准，消除「功能实现了但不完整」「代码写了但没测试」「PRD 说的但没验证」的模糊地带。

---

## 2. DoD 检查清单

每个任务/功能/PR 必须满足以下 **全部条件** 才可标记为「已完成」：

### 2.1 代码完成

- [ ] 功能代码已实现，覆盖 PRD/Spec 中定义的所有 AC
- [ ] 代码通过 `pnpm lint`（tsc 0 error + eslint 0 error）
- [ ] Rust 改动通过 `cargo check --all-targets`（如涉及）
- [ ] 无 `console.log`/`println!` 等调试残留（诊断日志除外，需标记 `[diag]`）
- [ ] UI 颜色使用语义 Token（`bg-pet-primary` 等），无硬编码 hex

### 2.2 测试覆盖

- [ ] 新增/修改的函数有对应的 Vitest 单元测试
- [ ] 测试覆盖了正常路径 + 边界条件 + 异常场景
- [ ] 全量 `pnpm test` 通过（不允许新增失败用例）
- [ ] Rust 改动有对应 `cargo test` 用例（如涉及）

### 2.3 文档同步

- [ ] AGENTS.md 已同步更新（目录结构/模块清单/版本号/坑点）
- [ ] 新增模块在 AGENTS.md §3.2 或 §3.3 有对应条目
- [ ] 踩坑记录已追加到 AGENTS.md §14 Known Gotchas
- [ ] CHANGELOG.md 已记录变更

### 2.4 国际化

- [ ] 新增 UI 文案已在 5 种语言（zh-CN/zh-TW/en-US/ja-JP/ko-KR）同步
- [ ] `pnpm i18n:check` 通过（如有）

### 2.5 构建 & 验证

- [ ] Rust 改动后执行了 `pnpm build` 并复制产物到 `artifacts/`
- [ ] 功能性改动后执行了完整编译验证（AGENTS.md Gotcha 11）
- [ ] 手动验证功能按预期工作（不仅仅是测试通过）

### 2.6 安全 & 隐私

- [ ] 无硬编码密钥/API Key/敏感常量
- [ ] 敏感数据落盘使用 AES-256-GCM 加密
- [ ] Tauri capability 权限最小化（如涉及新窗口/新 IPC）
- [ ] 无新增静默 `catch {}` 吞块（使用 `swallowedCatch` 工具）

### 2.7 可追溯性

- [ ] 代码包含 `@req` 注释关联需求 ID（如适用）
- [ ] 测试包含 `@see` 注释关联 AC（如适用）
- [ ] 变更有对应的影响评估（A/B 类变更）

---

## 3. DoD 等级

| 等级 | 适用场景 | 要求 |
|------|---------|------|
| **Full DoD** | 正式功能开发 | 全部 7 类检查项 |
| **Lite DoD** | Bug 修复 / 小优化 | §2.1 + §2.2 + §2.5 |
| **Hotfix DoD** | 紧急线上修复 | §2.1 + §2.5（事后补齐其余） |

---

## 4. 验证流程

```
任务完成 → 自查 DoD 清单 → 全量回归测试 → 同步文档 → 提交 Git → PR Review → 合并
```

不满足 DoD 的任务不得标记为已完成，不得提交到 main 分支。
