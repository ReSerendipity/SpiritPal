## #220 摘要类模块的「置信度」与「增量」是两个独立的谎
- **落点**：`lib/memory/memorySummarizer.ts`（TD-004）
- **坑一：置信度当装饰品**。`confidence: 0.85` 旁边写着 `// TODO: 从 LLM 响应中提取置信度`，但启发式结果同样顶着 0.85 —— 上游拿到 0.85 会以为「模型给的、很可信」。修法是**加 `source` 字段 + 按可观测量算置信度**（覆盖度、密度、来源三档上限），降级路径的上限必须低于正常路径，否则「降级」在数值上等于没发生。
- **坑二：「增量」实现比不做更坏**。原 `incrementallyUpdateSummary` 把新记忆丢给 `summarize()` 重算，旧摘要正文整段被覆盖掉，`generatedAt` 却刷新——用户看到的是「摘要更新了」，实际是「历史被删了」。判据：增量函数如果**没有引用旧的任何字段**就返回新结果，那不是增量，是覆盖。真增量至少要「用 id 集合判有没有新内容」（无新内容时零调用复用旧对象）+「旧摘要进提示词上下文」。
- **坑三：假延迟掩盖未接线**。`await setTimeout(500)` 让调用方「感觉像在调模型」，同时把「其实没调」这个事实藏了 500ms。桩里出现固定 delay + 本地启发式，等同于自证未接线。
- **负控要分两级**：先「换回 HEAD 旧文件」看新测试是否红（这级常常只是因为新导出符号不存在而红，证明力弱），再「保留新符号、只把行为退回桩」（忽略注入的 LLM / 置信度写回常量 / 增量改回重算）——这一级 8/12 红才是真杀伤力。只做第一级会误以为测试很硬。

## #221 权限函数的返回值就是诚信问题：「日志里有请求」不等于「用户授权了」
- **落点**：`lib/system/calendarIntegration.ts`（TD-008）
- **坑**：`requestPermission()` 三个分支各打一行 `console.log('Requesting ...')` 或 `console.log('Opening OAuth2 ...')`，然后**共用一句** `permissionGranted = true; return true`。日志读起来像「正在弹窗」，函数却已经答复「已授权」——上层没有任何办法分辨真假。判据：授权函数里如果**没有任何** `await` 拿到外部结果、却把 granted 置 true，那就是谎报。
- **修法**：授权结果只能来自注入钩子（`deps.requestPermission`）或真实系统调用；没有通道时**返回 false 并说明缺什么**，别用 true 换「流程走完」的假象。macOS 那种「读一次触发弹窗」的检查也必须返回 boolean，不能返回 void 让调用方自己脑补。
- **同类坑：播报/通知通道**。`sendReminder()` 只 `console.log` 也算「已播报」吗？不算。改成 `speak` 钩子 + 返回值 + `suppressed` 计数，才能区分「没人接这个钩子」与「播出去了」。
- **顺手抓到的真 bug**：60s 定时器 + 每次都重播窗口内全部事件 = 同一场会被连播 N 次。提醒类功能必须有 per-event 去重键（有 id 用 id，没 id 用 `title@startTime`），否则「提醒」会退化成骚扰。

## #222 `return []` 的空实现比不实现更坏：「没数据」与「没做」长得一模一样
- **落点**：`lib/nurture/dailyJournal.ts`（TD-005）
- **坑一：空数组是最难查的桩**。`fetchTodaysMemories` / `fetchTodaysActivities` 都 `return []`，上层于是产出一篇「标题正常、正文为空」的日记——没有异常、没有日志、没有告警。判据：**读取类函数的空返回必须有伴随信号**（是「真的没有」还是「没有实现」）。修法是加数据来源报告（`memorySource: injected|manager|unavailable`、`activitySource: injected|none`），让它自己说清楚。

## #224 三处「看起来在等网络」的多模态桩：假延迟 + 截断当提取 + 假截图路径，全都不报错
- **落点**：`src/lib/ai/multimodalLLM.ts` 的 `callVisionAPI` / `parseAnalysisResponse` / `analyzeScreenshot`（TD-002，2026-11-09 偿还）。
- **坑**：`await new Promise(r => setTimeout(r, 1000))` 被注释成「模拟 API 延迟」，调用方看到 1s 耗时便以为真发了请求；`parseAnalysisResponse` 拿 `response.substring(0, 200)` 当 `description`、`objects` 恒 `[]`，把「没提取」包装成「提取结果」；`analyzeScreenshot` 读 `join(process.env.TEMP, 'screenshot.png')` 这条**不存在的路径**，必然在 stat 处失败——而真实截屏通道 `take_screenshot` 返回的是 base64，本来就无路径可读，「把路径补对」这个方向是错的。
- **判据**：桩的特征不是「有 TODO 注释」，而是**假延迟 / 恒空集合 / 恒定默认值 + 不做状态回报**。查一条链路有没有真提交点，看最后一跳能否区分「拿不到」与「拿到了但是空」；区分不了就是桩。本例里 `analyzeImage` 还固定 `guessMimeType('jpeg')`，png/webp 一律按 jpeg 上传——用「.png 后缀装 JPEG 字节」这种字节层证据能戳破所有「按扩展名猜」的写法。
- **修法**：注入面（`VisionChatBackend` / `ScreenshotProvider`）+ zod schema 校验 + `status: ok|unavailable|error` 三态 + `getStatus()` 状态查询；负控必须把实现**打回桩行为**，只断言「函数被调用过」的用例在负控下会大面积通过。既有测试若断言的是桩文案本身（「我收到了一张图片」），改断言要逐条在台账与测试文件头写明原因，否则会被读成「为过测试改断言」。另：负控脚本用 PowerShell `.Replace()` 以 `\r\n` 去匹配 LF 文件会**静默不命中**（`patched=False` 却照样往下跑测试，得出「负控无效」的假结论）；要么改用 python 按 `\n` 精确替换并断言命中次数=1。
